# 0014 — EIA-930: the API daily from 2019, the bulk files once for 2015–2018

**Status:** Accepted · **Date:** 2026-11-01

## Context
EIA-930 (the Hourly Electric Grid Monitor) is EIA's hourly record for every US balancing authority, ISO New England included (`ISNE`). For this project its value is **history**: hourly demand and ISO-NE's own day-ahead demand forecast reach back years before ISO-NE's API does ([0013](0013-isone-backfill.md): about mid-2019 at best). It's also an independent, revised series to check ISO-NE's feeds against. Exploring on 2026-10-31 and 2026-11-01 ([data-sources.md](../data-sources.md#eia-930-hourly-electric-grid-monitor)):

- **API** (`api.eia.gov/v2/electricity/rto/{region-data,fuel-type-data}`, free key): long records, one per hour × measure (`period`, `respondent`, `type`, `value`, …). For ISNE it starts at **2019-01-01**: region data 274,613 rows, fuel type data 591,572.
- **Bulk six-month files** (no key): wide CSVs, one row per balancing authority × hour, from **2015 Jul–Dec**. Their columns change over time. The 2015 file has 19 columns: demand, the day-ahead forecast, net generation and interchange, but **no generation by fuel**. 2019's has 44, 2026's 65.
- **They agree:** for 2019-01-01 06:00 UTC, the API's D, DF, NG, TI (11,614, 11,500, 8,902, −2,712) and its fuels match the bulk file's columns exactly. The API's `period` is the bulk file's "UTC Time at End of Hour": EIA labels each hour by its **end**. For ISNE the raw and "(Adjusted)" columns were identical in every hour of both files checked (2015 H2, 2019 H1).
- **Revisions:** EIA regenerates every bulk file daily, back to 2015, so any hour can change.

## Decision
- **Two scheduled jobs from the API, daily** (05:15 Eastern, before the 06:20 transform): `eia-region-data` (D, DF, NG, TI) and `eia-fuel-type-data` (generation by fuel), into `bronze.eia_region_data` and `bronze.eia_fuel_type_data`. Each run re-pulls the **last 14 days**; bronze keeps every version, and silver keeps the newest ([0001](0001-append-only-bronze.md)). Daily, not every 6 hours: ISO-NE's own feeds are the fresh ones, and EIA is the history and the cross-check.
- **Bronze keeps the API's field names**, with `-` written `_` (BigQuery allows no hyphens): `respondent_name`, `type_name`, `value_units`. `period` is stored as a UTC TIMESTAMP, still the hour's end; silver converts to hour starts.
- **Backfill 2019 on through the same jobs** (backfill mode, `common/backfill.py`): a month per call (two pages for fuel types), ~300 calls in all.
- **2015-07 to 2018-12 from the bulk files**, through a backfill-only job (`eia-region-data-bulk`) into **its own table**, `bronze.eia_region_data_bulk`, reshaped into the API's long form (same columns), so silver reads both the same way. Kept separate, not merged into the API's table, so each bronze table has one source. Only the four measures the API has (raw columns, which match the API); the files' other columns (imputed and adjusted variants, "Sum(Valid DIBAs)") are left behind.
- **No fuel history before 2019:** the 2015 files have none, and ISO-NE's own fuel mix covers mid-2019 on.
- **The key never reaches a log:** it travels as a query parameter, so `fetch()` redacts it from any error it reports.

## Consequences
- **Size and cost:** daily runs ~5,000 rows (~1.8M rows, ~165 MB a year, most of it re-pulled versions); the API backfill ~870,000 rows; the bulk backfill 7 files (~280 MB downloaded) → ~120,000 rows. Calls are a few hundred in all. Effectively $0.
- **Hour labels differ by source:** EIA's are hour *ends*, ISO-NE's and Open-Meteo's hour *starts* (Open-Meteo's sums cover the hour ending at its label). Silver converts EIA's, so gold joins line up.
- **Demand history runs 2015-07 on**, with ISO-NE's day-ahead forecast alongside: the benchmark a load model has to beat, for 11 years.
- If EIA ever stops regenerating the 2015–2018 files, bronze already has them.
